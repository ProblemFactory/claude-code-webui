### ws-handler.js (heartbeat + attach rebuild)

  ws-handler.js — **`default:` case (Plugin Ph1): the `switch (data.type)` had NO default, so an unknown type vanished — no log, no telemetry, no reply, the sender waited forever.** Now `noteUnknownWsType(telemetry, type)` logs once per type per 10 minutes with the running count (a chatty stale client cannot flood the journal), records telemetry `ws-unknown-type` per occurrence, and replies `{ type:'error', code:'unknown-type', message, unknownType, reqId? }` — **deliberately WITHOUT sessionId**: ws.js routes session-scoped handlers by `d.sessionId`, and every client `error` consumer (chat-view's branch, terminal's per-session handler, session-lifecycle's create/attach/view handlers) keys on `msg.sessionId`/`msg.reqId` — a session-scoped error frame is what flips a live window into the exited/read-only path, and an unknown TYPE is not a dead session. `reqId` IS echoed so a `ws.request()` caller fails fast. `telemetry` joined WS_CTX_CONTRACT for it.

  ws-handler.js — **2.369.16 (userW inc-mtndq0vb): the first-attach history rebuild is TIME-SLICED and single-flight (`normalizers.rebuildHistory` → `convertHistoryAsync`, ~25ms slices yielding to the loop; concurrent attaches await one promise; live records arriving mid-rebuild queue on `session._rebuildQueue` and replay in order; `_historyLoaded` set after success). Every live record enters a session normalizer through `normalizers.feedLive(session, msg)` — a direct `session._normalizer.processLive` call is a gate bypass (test-attach-rebuild counts them = 0). Rebuilds are FIFO (one at a time — fair slicing landed every window at the total time) and the attach re-acks every 10s with `{progress}` while waiting/converting (client ladder extends on fresh acks, 15min bound), then re-checks the session is still live before sending `attached`. The heartbeat lives in src/server/ws-heartbeat.js and is STALL-AWARE with TWO detectors: tick lateness AND a 1s loop-gap pulse (a 30–35s block starting right after a ping ends with the tick only seconds late but the pong unread — the review's blind band); a tainted round terminates nobody, bounded at 6 consecutive pong-less tainted rounds; terminations are logged + telemetered. The old inline interval terminated a live client after a 4-minute rebuild stall and dropped its queued kills. `kill` replies `killed {sessionId: REQUESTED id, resolvedId, ok, reason}` to the requester in both outcomes (`exited` only reaches attached clients) — the client's `killSession` sends the backendSessionId fallback frame as a one-shot and resend-chases only the plain kill (a resent fallback would kill the resumed successor), with its watchdog disarming the request.**

## src/server/wrapper-files.js (2.339.2 resolver + 2.364.1 capability reader)
